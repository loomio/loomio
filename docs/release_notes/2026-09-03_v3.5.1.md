## Notification settings and catch-up emails

Account defaults, group memberships, and individual threads now use the same three notification levels: **Catch-up only**, **When notified**, and **All activity**. Email and push use independent levels, while notifications under the bell remain available regardless of external delivery settings.

Existing email settings are migrated to the corresponding email level. The legacy **Mute** state is consolidated into **Catch-up only**, and existing **All activity** settings remain in place. Loomio no longer changes a thread to **All activity** when someone comments, votes, or otherwise participates, and the **Subscribe on participation** preference has been removed. Mentions and closing-soon reminders now follow the applicable group or thread setting instead of separate account preferences.

Catch-up emails now begin with unseen notifications, followed by unread discussions and polls. Members can choose daily, every-second-day, or weekly delivery. Opening or previewing an email does not mark its contents as read; the email includes an explicit **Mark catch-up as read** action.

Thread navigation identifies email-only **All activity** and **When notified** settings explicitly, distinguishing them from settings that also enable device notifications.

## Installable web app and browser push

Supported browsers can install Loomio and open it from a home screen or app launcher. On iPhone and iPad, installation uses Safari's **Add to Home Screen** action. The installed web app still requires an internet connection and is not a native mobile app.

Browser push is optional and disabled until the operator configures VAPID credentials and a member enables it in a browser. Each enabled browser is tied to the authenticated session that registered it. Signing out revokes that browser's subscription; changing a password removes subscriptions belonging to the other sessions that are signed out. Push endpoint URLs are limited to the supported Apple, Google, and Mozilla providers, and endpoint and encryption-key values are not returned by the API.

New installations receive VAPID keys automatically from `create_env.sh`. Existing installations can append a key pair to `.env` with the one-line command in the updated [upgrade guide](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md#350-browser-push-notifications). Keep the generated pair unchanged across deployments; replacing it invalidates existing browser subscriptions.

## Poll reminders and interface fixes

Reopening a poll no longer sends a new poll announcement automatically. After the new closing time is saved, Loomio opens the reminder form so an eligible coordinator can choose recipients and send an in-app, email, or push reminder explicitly.

This release also fixes several interface and data-handling problems: standalone poll search results open through their poll route; unavailable document previews fail cleanly; tasks serialize for every supported record type; tags render while group records load; tag expansion is hidden when every available tag is already shown; and announcement forms retain valid target parameters.

Operators can replace the sidebar user-manual title, subtitle, or URL with `LOOMIO_HELP_TITLE`, `LOOMIO_HELP_SUBTITLE`, and `LOOMIO_HELP_URL`. Unset values continue to use Loomio's translated defaults.

See [PR #12781](https://github.com/loomio/loomio/pull/12781) and the [notification settings documentation](https://www.loomio.com/docs/en/user_manual/users/email_settings).

## Database and API compatibility

This release contains ten database migrations. They split notification levels into email and push channels, add session-owned push subscriptions, remove obsolete notification-preference and retry-state columns, add notification audience provenance, set daily catch-up as the default for new accounts, and repair topics with missing timeline positions. The timeline repair runs once for each affected topic and removes obsolete closing-soon, expired, and poll-option lifecycle rows after preserving their notification subjects. No manual backfill command is required.

The internal `/api/v1` client contract now uses `volume_email` and `volume_push` for memberships and topic readers, and `volume_email_default` and `volume_push_default` for account defaults. Calls that update notification volume must send the channel-specific fields. The removed legacy fields are `volume`, `default_membership_volume`, `email_on_participation`, `email_when_mentioned`, and `email_when_proposal_closing_soon`. New authenticated push-subscription endpoints are available under `/api/v1/push_subscriptions`. There are no intended B2 or B3 API changes.

## Upgrade

Make and verify a current database backup, set `LOOMIO_CONTAINER_TAG=3.5` in `.env`, then run:

```sh
./update.sh
```

The normal update runs all required migrations. VAPID settings are optional and are needed only for browser push; the installable web app and the rest of Loomio continue to work without them. No other configuration or manual operator action is required when upgrading from Loomio 3.4.2. Instances running Loomio 3.5.0 should upgrade directly to this release.
