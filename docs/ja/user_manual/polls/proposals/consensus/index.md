# コンセンサス

コンセンサス提案は、関係者全員の合意を目指します。標準の回答では、参加者は同意、棄権、反対、ブロックを選べます。

このページでは、コンセンサス提案の進め方を説明します。議論や意向確認から修正、結論までの一連の流れは、[コンセンサスのプロセス](/en/guides/making_decisions/consensus_process)を参照してください。

<!-- translation-section: when-to-use-consensus -->

## コンセンサスを使う場面

多くの人が決定に責任を持ち、懸念についてグループで話し合う用意がある場合に、コンセンサスを使います。共通の基準、運営上の取り決め、戦略的な方針、グループ全体に影響する決定に適しています。

コンセンサスでは通常、投票の前に議論を重ね、提案を練り上げます。グループにとって**ブロック**が何を意味し、どのような結果をもたらすかを定めてください。ブロックを使わない場合は、テンプレートを編集してその選択肢を削除します。

<!-- translation-section: example-adopt-a-bottle-return-standard -->

## 例：瓶の返却基準を採用する

オーツミルク協同組合は、保証金、回収、洗浄、食品安全の記録、報告に関する基準を作成しました。すべてのチームがこの基準を使うため、採用前にコンセンサスを得ようとしています。

<!-- translation-section: set-up-the-proposal -->

## 提案を設定する

検討する合意内容を漏れなく記し、参考資料へのリンクを追加します。各回答の意味、特に反対とブロックの違いを説明します。質問や修正に十分な時間を設けます。

![](form.png)

<!-- translation-section: vote -->

## 投票する

参加者は自分の立場に合う回答を選び、その背景にある関心や懸念を説明します。ブロックする理由には、提案を採用すると基本的な必要条件や合意済みの原則にどう反するかを示します。

![](../proposal_consensus_voting.png)

<!-- translation-section: read-the-results -->

## 結果を確認する

グラフには回答の内訳が示されます。反対意見とブロックの理由をすべて確認します。コンセンサスは懸念を解消していく過程であり、同意票の数だけで決まるものではありません。

![](../proposal_consensus_results.png)

<!-- translation-section: share-an-outcome -->

## 結論を共有する

提案の投票が終了したら、結論を共有します。グループが合意に達した場合は、最終的な合意内容と担当者を記録します。合意に至らなかった場合は、修正する内容と、グループがいつ提案の検討を再開するかを記録します。結論の仕組みについては、[結論を共有する](/en/user_manual/polls/intro_to_decisions#5-share-an-outcome)を参照してください。
