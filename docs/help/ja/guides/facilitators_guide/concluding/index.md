# 結論を出す

![](cover.jpg)

<!-- translation-section: outcomes-next-steps -->

## 結論と次のステップ

結論を確認することは、協働で進めるディスカッションの目標を達成できたと実感するために重要です。ファシリテーターは、決定したことをまとめて参加者に伝え返すことで、グループが次のような重要な問いへの答えを持ち帰れるよう支援できます。

* 何をしましたか？
* それにはどのような意味がありますか？
* これから何が起こりますか？
* 自分にはどのような責任がありますか？
* この経験を通じて、何が変わりますか？

これらの問いへの答えは、実行する項目のように具体的な場合もあれば、共通理解を深めることのように抽象的な場合もあります。

Loomioでは

* [結論](/en/user_manual/polls/intro_to_decisions#5-share-an-outcome)は、とても重要なツールです。提案の終了だけでは、十分な締めくくりにはなりません。何が決まったかを明確にまとめる必要があります。そのために結論機能があります。
* Loomioのディスカッションの多くは、提案を使ったり結論を公開したりしなくても、自然に終わります。こうしたディスカッションにも大きな価値があります。後で参照できるように、背景説明欄に結論の要約を追記すると役立ちます。
* 特定の人に実行する項目がある場合は、その人の名前を@メンションすると通知が届きます。

## 報告と学びの整理

経験の意味を理解するには、それがより大きな流れの中でどのような位置を占めるのかを考える必要があります。取り組み全体の進展の中で、この時間にはどのような意味があったのでしょうか。この経験から得た理解は、体験談、報告書、変化、行動の呼びかけなど、どのような形になるのでしょうか。

経験はその場で生まれますが、その経験を整理して名前を付け、活用したり参照したりできるようにすることで、影響が広がることがよくあります。そうしなければ、内容を忘れたり、その場にいなかった人が取り残されたり、後で同じことを繰り返す必要が生じたりする可能性があります。具体的な記録や報告は、協働を進めるうえで役立ちます。

Loomioでは

* Loomioでは、プロセスの一部として記録が自然に残ります。追加の作業をしなくても、グループが後から参照できる豊富な記録が蓄積されます。
* 学びの整理や記録の保存を支援する機能として、検索機能、「過去の決定」の一覧、ディスカッションの印刷機能があります。
* プレミアムプランでは、グループのLoomioデータをすべてエクスポートできます。
* 多くのグループは、さまざまな場で生まれた内容をLoomioにまとめています。例えば、Loomioに会議の案内を投稿して議題を作成し、対面で会議を行った後、議事録をLoomioに投稿し、同じスレッドで関連する決定を行います。これにより、Loomioに自然に記録を蓄積する仕組みを、オンライン以外の活動にも広げられます。

## ディスカッションを行動につなげる

話し合いの場の外にある現実に、再び向き合う時が来ます。実行方法を気にせず、考えや気持ちを整理するだけでよい場合もあります。しかし通常、グループが目標を達成するには、結論を実際の行動につなげる必要があります。この移行も、ファシリテーションを通じた一連の経験の一部です。

この段階で、協働のプロセスは組織のほかの仕組みと関わるようになります。ファシリテーターは、それらとどのように連携するかを整理する必要があります。関係する仕組みには、次のようなものがあります。

* **権限** — 実際に決定を行うのは誰ですか？ここで考えを実現するには、何が必要ですか？
* **マネジメント** — ほかの優先事項とどのように関係しますか？どのような依存関係が考えられますか？
* **役割の委任** — 次のステップに責任を持つのは誰ですか？その人に説明責任はありますか？
* **情報共有** — このプロセスやディスカッションを、ほかの人にどのように伝えますか？その人たちが知る必要のあることは何ですか？
* **事務管理** — ある仕組みの情報を、タスク管理ツールや情報共有ツールなど、別の仕組みにどのように入力しますか？情報はどこに保存しますか？

これらの点に障害がある場合、締めくくりの段階まで気付かずにいると、取り組みに悪影響が生じることがあります。例えば、参加者に、決定した変更を実行する権限が実際にはなければ、挫折感につながります。プロセスを設計する際には、実行時の現実的な条件をあらかじめ考え、それに合わせて協働の範囲を定めます。


Loomioでは

* 決定に基づいて行動する人の名前を@メンションできます。
* 多くのユーザーは、定期的な対面会議でLoomioの決定を確認したり、結論をタスク管理のプロセスに移したりして、Loomioの内容を組織のほかの仕組みに組み込んでいます。
* 明確な決定を行うと、自然に「では、これをどう進めていきますか？」という問いが生まれます。
* Loomioのグループを作ると、「この決定を行動につなげるには、誰がここに参加する必要がありますか？」といった重要な問いが明らかになることがよくあります。主要な関係者、リーダー、管理者が参加していないと、先に進めなくなることがあります。

## 最後まで締めくくる

適切に終えることは重要です。プロセスを締めくくるには一定の手順があり、それを省くと参加者は落ち着かない気持ちになります。時間切れによって終わることもあれば、特定の目標を達成した時に終わることもあります。一人ひとりとグループ全体が、プロセスや段階の完了を実感できているかどうかを示す、言葉や態度などの手がかりに注意を払います。

参加者は、実際にいつ終わるのかをリーダーやファシリテーターに確認しようとすることが多いため、明確に伝えると役立ちます。セッションの終了を明言し、決定や次のステップを振り返り、全員に別れの挨拶をすることが、締めくくりの合図になる場合もあります。また、終了時に一人ずつ振り返りを共有するチェックアウトなど、グループで定着した方法がある場合もあります。セッションを曖昧なまま終わらせると、すっきりしない気持ちが残ります。

Loomioでは

* Loomioで締めくくりを最も明確に示す方法は、決定の結論を公開することです。
* それ以上の変更を防ぎ、不要な投稿が増えるのを抑えるために、[スレッドをロックする](/en/user_manual/discussions/using_discussions/#lock-or-unlock-a-thread)機能を使うグループもあります。
* グループの無効化は、最も明確な終了の方法です。無効化すると、誰もそれ以上投稿できなくなります。
* Loomioのグループは、活動が活発になったり落ち着いたりしても存続できます。そのため、今後活動を再開する予定がある場合でも、特定の段階の終了などの節目を確認すると役立ちます。
