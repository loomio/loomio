Loomio 3.7.0 adds private submission workflows, reasoned membership-request declines, following for open Groups, and expanded participation reporting. It also improves query performance and mobile editing while clarifying the lifecycle of hidden and deleted templates.

- **New:** Let non-members submit private discussions to a closed group through discussion templates
- **New:** Decline membership requests with a reason delivered by email and allow applicants to re-apply
- **New:** Follow updates from open Groups without becoming a member
- **New:** Report delegate activity and identified voting participation by user
- **Fix:** Collapse the formatting toolbar by default on mobile without changing the desktop preference
- **Fix:** Reduce repeated record-loading and controller serialization queries

## Private submissions

Administrators of Open and Closed groups can enable **Non-members can start discussions**. A user with an account can then select one of the group's discussion templates and submit a discussion without joining the group. The submitter is added to that discussion as a guest, so they can see and participate in it without gaining access to other private group discussions.

For a private nomination, application, complaint, safety concern, or other submission process, create a Closed subgroup for the reviewing panel, add reviewers as members, enable non-member discussions, and provide the appropriate discussion templates. Reviewers can invite another person, such as a nominee, into an individual discussion when their input is required. See [Collect private submissions](https://www.loomio.com/docs/en/user_manual/discussions/private_submissions).

## Membership requests

Group administrators can decline a membership request with a required reason. Loomio always sends that reason to the applicant by email; notification preferences cannot disable this transactional message. The in-app notification states only that the request was declined and does not include the arbitrary-length reason. **Ignore** remains available for closing a request without a reason or email.

After a request is declined or ignored, the applicant can submit a new request with a corrected message. Approval remains immediate and does not ask the administrator for a comment.

## Following open Groups

Users can follow an open Group's public updates without becoming members. Followed discussions, comments, polls, and other unread thread activity appear in the user's normal catch-up email. Following does not grant membership, access to private content, or permission to participate, and users can unfollow from the Group page.

## Participation reports

Participation reports now include a **Delegates only** filter for actions per user and a **Voting record per user** section. The voting record shows identified ballots issued, cast, and missed; anonymous polls are excluded from per-user voting records. Delegate status is also visible in poll and thread invitee lists, and integrations can retrieve the aggregate report through the User API.

## Other changes

The mobile formatting toolbar starts collapsed and keeps a preference separate from desktop. Poll chart icons now use native SVG. Record loading, notification subjects, and controller serialization perform fewer repeated queries. Several abandoned poll and notification settings and routes have been removed.

## Database and API compatibility

This release contains seven database migrations. They add the non-member discussion permission, membership-request decision timestamps and decline reasons, and Group follows. Discussion and poll templates now use `hidden_at` and `hider_id` for reversible hiding while `discarded_at` and `discarded_by` retain their deletion meaning. The migrations also remove the retired discussion-template task data and `polls.voter_can_add_options` column.

The participation report is available through the User API. Operators with custom database queries that use the removed columns or interpret template `discarded_at` as visibility state must update those queries. No environment-variable changes are required.

## Upgrade

Make and verify a current database backup, set `LOOMIO_CONTAINER_TAG=3.7` in `.env`, then run:

```sh
./update.sh
```

The normal update runs all required migrations. Restart every application and worker process after updating. After the release is available, confirm that the application and worker containers report version 3.7.0.
