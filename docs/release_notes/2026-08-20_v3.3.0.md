# Loomio 3.3.0

Loomio 3.3.0 completes the transition to detached anonymous voting. It removes
the stance-based anonymous voting implementation retained temporarily by 3.2.0
and prevents that legacy poll format from being stored again.

- **New:** Anonymous polls and identified polls now use separate storage models with enforced poll configuration
- **Fix:** Stance records, serializers, events, search, and exports no longer contain legacy anonymous-voting exceptions
- **Fix:** The upgrade closes and converts every remaining legacy anonymous poll before removing the old storage model

## Upgrade path

Make and verify a current database backup before upgrading. Set
`LOOMIO_CONTAINER_TAG=3.3` in `.env`, then run:

```sh
./update.sh
```

Loomio 3.3 supports a direct upgrade. Its database migration closes every
remaining legacy anonymous poll through the 3.2 close path, converts each poll
to detached anonymous ballots, and verifies the conversion before removing the
legacy runtime code. This includes open, scheduled, discarded, archived, and
polls without a closing time. The migration can take significant time on an
instance with many legacy anonymous polls; do not interrupt it.

Loomio 3.2.0 remains an optional holding release for instances with important
legacy anonymous polls still running. Those polls remain open normally on
3.2.0 and are converted when they close. Upgrade to 3.3 only when any polls
that must remain open are ready to be closed.

The conversion back to stance storage is intentionally irreversible. Closing a
poll through this upgrade publishes the same expiry event, notifications, and
timeline updates as reaching its configured closing time.

The migration commits one poll at a time and is safe to rerun after an
interruption. Its final guard checks every poll and stops before adding the new
constraint if a conversion could not be completed, reporting the count and the
first poll IDs for diagnosis.

## Anonymous-voting storage boundary

After migration, an anonymous poll must use detached `AnonymousBallot` records,
and a poll using `Stance` records must be identified. Rails validations enforce
the storage boundary for application writes. A PostgreSQL check constraint
prevents direct writes and imports from combining anonymous polls with stance
voting, or identified polls with anonymous-ballot voting.

The migration removes any obsolete queued legacy-conversion jobs after it has
verified that no legacy poll remains. The conversion worker, transitional
cleanup and audit services, and their operator rake tasks are no longer part of
the application.

Detached ballots, named electorate records, source receipts, poll-level
attachments, aggregate results, and read-only plain-text reasons preserved from
legacy votes remain available. No ballots or preserved reasons are deleted by
the 3.3 migration.

## Compatibility and rollback

The application schema remains compatible with PostgreSQL versions supported by
Loomio 3.2. Downgrading the application does not recreate stance records for
polls already converted to detached ballots. If rollback is required, restore
the pre-upgrade backup together with the 3.2 application version.
