# コンセンサス

コンセンサスの提案は、関係する全員が支持できる合意を目指します。既定の回答では、参加者は賛成、棄権、反対、ブロックを選択できます。

このページでは、コンセンサスの提案を実施する方法を説明します。ディスカッションと意向確認から修正、結論までの一連の流れについては、[コンセンサスのプロセス](/en/guides/making_decisions/consensus_process)を参照してください。

<!-- translation-section: when-to-use-consensus -->

## コンセンサスを使う場面

多くの人が決定を自分たちのものとして受け止めることが重要で、グループが懸念の解消に共に取り組む準備ができている場合に、コンセンサスを使います。共通の基準、組織運営に関する合意、戦略上の方針、グループ全体に影響する決定に適しています。

コンセンサスでは通常、投票の前にディスカッションを行い、提案を練る必要があります。グループにおける**ブロック**の意味と、ブロックされた場合の対応を定めます。ブロックを使わないプロセスの場合は、テンプレートを編集してその選択肢を削除します。

<!-- translation-section: example-adopt-a-bottle-return-standard -->

## 例：瓶の返却基準を採用する

Oatmilk協同組合は、預かり金、回収、洗浄、食品安全に関する記録、報告を含む基準を作成しました。すべてのチームがこの基準を使うため、採用する前にコンセンサスを目指します。

<!-- translation-section: set-up-the-proposal -->

## 提案を設定する

検討する合意内容の全体を明記し、関連情報へのリンクを付けます。各回答の意味、特に反対とブロックの違いを説明します。質問や修正のために十分な時間を設けます。

![](form.png)

<!-- translation-section: vote -->

## 投票する

参加者は自分の立場に合う回答を選び、その背景にある利害や懸念を説明します。ブロックの理由では、提案の採用が基本的なニーズや合意済みの原則に反する理由を明確にします。

![](../proposal_consensus_voting.png)

<!-- translation-section: read-the-results -->

## 結果を確認する

グラフには回答の割合が表示されます。反対とブロックの理由をすべて確認します。コンセンサスは、賛成票を数えるだけでなく、懸念を解消していくプロセスです。

![](../proposal_consensus_results.png)

<!-- translation-section: share-an-outcome -->

## 結論を共有する

提案を締め切ったら、結論を共有します。グループが合意に達した場合は、最終的な合意内容と担当者を記録します。合意に達しなかった場合は、修正する内容と、グループが提案を再検討する時期を記録します。結論の仕組みについては、[結論を共有する](/en/user_manual/polls/intro_to_decisions#5-share-an-outcome)を参照してください。
