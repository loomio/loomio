Warning! If you have not read the release notes for v3.4.0, please stop and read those before upgrading to v3.4.1.

Loomio 3.4.1 fixes three vulnerabilities in outbound URL validation, link previews, and rich-text rendering. Instances running Loomio 3.4.0 or earlier should upgrade.

- **Fix:** Block private IPv4 destinations represented as IPv4-mapped IPv6 addresses
- **Fix:** Render fetched link-preview titles and descriptions as plain text
- **Fix:** Prevent rich-text media and task attributes from being reparsed as HTML

## Outbound request validation

Loomio now normalizes IPv4-mapped IPv6 addresses before applying its outbound request blocklist. This prevents link previews and other protected server-side HTTP clients from reaching loopback, private-network, link-local, or cloud metadata addresses through that alternate representation. Public IPv4-mapped destinations remain supported.

See [GHSA-8hf6-x392-558f](https://github.com/loomio/loomio/security/advisories/GHSA-8hf6-x392-558f).

## Link-preview rendering

Titles and descriptions fetched from external pages are now reduced to plain text before the API returns them. The client also renders preview metadata as text rather than HTML. This prevents a page controlled by an attacker from running markup in the Loomio session of a member who previews its link.

See [GHSA-c9x8-9fw9-xx33](https://github.com/loomio/loomio/security/advisories/GHSA-c9x8-9fw9-xx33).

## Rich-text rendering

When Loomio converts embedded video, audio, iframe, and task metadata for email, chatbot messages, or server-rendered pages, attribute values are now assigned through the HTML document API and cannot be interpreted as new markup. Ordinary media links, thumbnails, labels, and task due dates continue to render normally.

See [GHSA-wx5m-5f9h-333g](https://github.com/loomio/loomio/security/advisories/GHSA-wx5m-5f9h-333g).

These issues were reported by [lassiiiiii](https://github.com/lassiiiiii).

## Upgrade

Make and verify a current database backup, set `LOOMIO_CONTAINER_TAG=3.4` in `.env`, then run:

```sh
./update.sh
```

This release has no new database migrations, configuration requirements, or API compatibility changes.
