Loomio 3.8.1 lets people follow updates from open groups without joining and improves how group administrators respond to membership requests. It also removes repeated content from catch-up emails and fixes voting bounds when meeting poll options change.

- **New:** Follow updates from an open group without becoming a member
- **New:** Decline a membership request with a reason and let the applicant submit a corrected request
- **Fix:** Show notification content only once in catch-up emails
- **Fix:** Keep required voting bounds aligned with the current options in meeting polls
- **Fix:** Keep long attachment filenames within the editor

## Following open groups

Signed-in users can turn on **Follow updates** on an open group page to include unread discussions, comments, polls, and other thread activity in their regular catch-up email. Following a group does not grant membership or permission to participate. Users can turn the setting off from the same group page.

## Membership requests

Group administrators can decline a membership request with a required reason. The applicant receives the reason by email and sees it on the group page, where they can submit a corrected request. Administrators can instead ignore a request without notifying the applicant; an ignored request continues to prevent another application.

Responses to membership requests are final. A request that has already been approved, declined, or ignored cannot later be changed to another response.

## Catch-up emails

Notification summaries no longer repeat full discussion, comment, or poll content above the unread-thread section of a catch-up email. The content remains available once in the unread thread.

## Other fixes

Meeting polls that require a response for every option now recalculate their minimum and maximum choice counts when dates are added or removed. Long attachment filenames now wrap inside the editor instead of overflowing its boundary. Delegate status changes are included in membership audit history, and the instance administration group page no longer displays subscription links when the subscription routes are unavailable.

## Database and API compatibility

This release contains no database migrations and requires no environment-variable changes.

The membership-request endpoint used by the web client changed from `GET /api/v1/membership_requests/my_pending` to `GET /api/v1/membership_requests/mine`. It now returns the signed-in user's latest request for the selected group, including a decline reason when present. The group-follow deletion endpoint now uses the resource route `DELETE /api/v1/group_follows/:id`; for this endpoint, `:id` is the group ID. API clients using the previous routes must update with this release.
