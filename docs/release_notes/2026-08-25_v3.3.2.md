Loomio 3.3.2 is a security release that prevents malformed ballots from
manipulating or corrupting poll results. It also extends the default validity
of sign-in links and codes sent by email to 24 hours.

- **Fix:** Enforce each poll type's complete score, choice-count, and ranking rules before storing a ballot
- **Fix:** Reject negative choice scores in the application and database
- **New:** Keep emailed sign-in links and codes valid for 24 hours by default

## Ballot integrity

An ordinary group member could submit a crafted ballot that did not follow the
poll's configured rules. This could inflate a ranked-choice or STV score,
record contradictory proposal positions, cancel other voters' contributions,
or prevent a proposal result from displaying correctly.

Identified and detached-anonymous ballots now share one validation boundary.
Before storing a ballot, Loomio checks score and choice-count bounds, dot
budgets, contiguous ranking sequences, option ownership and uniqueness, and
`none_of_the_above` consistency. PostgreSQL constraints also reject new or
updated ballot choices with negative scores when a write bypasses application
validation.

Negative score scales are no longer supported. Polls that need a bipolar scale
must use nonnegative values, such as `0..10` with 5 as the neutral value.
Historical ballots and closed results are not rewritten.

See [GHSA-vw3c-8jvc-x67p](https://github.com/loomio/loomio/security/advisories/GHSA-vw3c-8jvc-x67p).
Reported by [lassiiiiii](https://github.com/lassiiiiii).

## Sign-in links and codes

Sign-in links and codes sent by email now remain valid for 24 hours instead of
one hour. They remain single-use, and the hourly cleanup job retains them until
their configured expiry. Operators can override the default with
`LOGIN_TOKEN_EXPIRATION_MINUTES`.

## Upgrade

Make and verify a current database backup. Set `LOOMIO_CONTAINER_TAG=3.3` in
`.env`, then run:

```sh
./update.sh
```

The upgrade backfills legacy ballot configuration from `polls.custom_fields`
into empty first-class poll columns. Existing column values take precedence,
blank legacy values are treated as absent, and the JSON is left unchanged. The
migration stops before updating any polls if it finds a nonblank legacy value
that is not a PostgreSQL integer; the error identifies the affected poll and
field so the value can be reviewed before retrying the upgrade.

The new `score >= 0` constraints apply to new or updated choice rows without
validating historical rows. Existing negative values therefore do not block
the migration, but a historical choice containing one cannot be updated while
it remains negative.
