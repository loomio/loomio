# Loomio 3.1.6

This security and feature release prevents an SSRF bypass involving IPv6
transition addresses. Operators should upgrade promptly. This release contains
no database migration and requires no new environment variable.

- **Fix:** Block SSRF bypasses using IPv4-compatible, NAT64, Teredo, and 6to4 addresses.
- **New:** Support light and dark color preferences in compatible email clients.
- **New:** Configure theme gradients, surface text colors, application bars, and navigation drawers.
- **Fix:** Include non-secret subgroups in parent-group exports and improve group imports.
- **Fix:** Process bulk invitation requests of 2,000 or more addresses before the request timeout.
- **Fix:** Stop blocked inbound emails from creating administrator notifications.
- **Fix:** Improve browser error reporting, forms, and chat integration feedback.

## SSRF protection for IPv6 transition addresses

Loomio now rejects IPv4-compatible, NAT64, Teredo, and 6to4 addresses when
validating destinations for server-side HTTP requests. Without these checks, a
URL using an IPv6 transition address could bypass the existing restrictions on
requests to private, loopback, link-local, or cloud-metadata destinations.

This issue is rated High (CVSS 7.7) and tracked as
[GHSA-4pxh-928r-gv9p](https://github.com/loomio/loomio/security/advisories/GHSA-4pxh-928r-gv9p).

The shared protection covers link previews, chat and Matrix integrations, and
logos or avatars fetched from SSO providers. Redirects and DNS resolution
continue to be checked and pinned for each request.

The issue was reported by tonghuaroot. We thank them for reporting it to the
Loomio maintainers.

Upgrading applies the additional address restrictions immediately. Operators
who find evidence that a protected outbound request reached an internal or
cloud-metadata service should assess the response data and rotate any secrets
that may have been exposed.

## Email dark mode

Loomio emails now support the recipient's light or dark color preference in
compatible email clients. Clients without color-scheme support continue to use
the light presentation. Email buttons, poll options, results, and other
semantic colors remain distinct in both modes.

## Theme configuration

Operators can configure optional application background gradients separately
for light and dark modes. Theme configuration can also set text colors for
backgrounds, surfaces, primary colors, and accent colors, as well as separate
colors for the application bar and navigation drawers.

Existing solid-color themes continue to work without changes. The new settings
are documented in `deploy/env_template`.

## Groups, exports, and invitations

- Parent-group administrators now include every non-secret subgroup they can
  access when exporting a parent group. Secret subgroups remain excluded.
- Newly created public subgroups and subgroups visible to parent members are
  published to parent-group members immediately.
- Importing a group export reuses matching redacted users instead of creating
  duplicate records.
- Bulk invitations now insert users in one database operation so requests with
  2,000 or more addresses complete before the request timeout. Addresses are
  validated before insertion, and unrestricted invitation limits are handled
  correctly.

## Other fixes

- Blocked inbound emails no longer create administrator notifications.
- Expected REST authentication failures are recorded as HTTP error metrics
  without being reported as unhandled browser exceptions.
- Browser errors are sent directly to Sentry instead of passing through the
  application server.
- Form actions consistently use native form submission behavior.
- Group settings and chat integration forms provide clearer action labels and
  error handling.

## Upgrade notes

1. Edit `.env` and set the application image tag:

   ```sh
   LOOMIO_CONTAINER_TAG=3.1.6
   ```

   Use `3.1.6` to pin this release, or `3.1` to track the 3.1 patch series.

2. Run the update script from the deployment directory:

   ```sh
   ./update.sh
   ```

3. Confirm that the application, worker, and inbound-mail services are
   running.

No data migration, data backfill, or new environment variable is required.
