This release improves how groups reuse decision processes and manage participation. It also changes integration field names and worker configuration, so self-hosted operators and API users should read the upgrade notes before updating.

- **New:** Save discussions and polls as reusable templates; **Save as template** replaces **Make a copy** for polls.
- **New:** Restrict new attachments throughout a thread to thread admins and group admins.
- **New:** New threads and discussion templates allow multiple polls at once by default; existing settings are preserved.
- **New:** Authorized poll editors can change anonymity, voting method, and result visibility before voting opens.
- **Fix:** Saving polls rounded voting times down to the hour, and scheduled opening checks ran hourly. Selected minutes are now preserved, with opening and closing checked every minute.
- **New:** Invitation suggestions put the current group first, followed by delegates and connected chat rooms.
- **New:** Change your catch-up email schedule directly from an unsubscribe page.
- **New:** The User and Server APIs use `/api/user0` and `/api/server0`, with compatibility paths for existing integrations.
- **Fix:** Search indexing delayed content saves. Index updates now run after saving in a prioritized background queue.
- **Fix:** Adding voters could rewrite existing vote revision flags and deadlock with membership changes. Existing votes are preserved, and membership jobs retry transient deadlocks.
- **New:** Instance admins can see password and passkey adoption on the dashboard.
- **Fix:** Rack had multipart parsing, host validation, and static-header security flaws. Rack 3.2.8 includes the fixes.

## Reusable discussion and poll templates

Use **Save as template** in a discussion, proposal, or poll's action menu to reuse its content and settings. Review the prefilled template form before saving it to the group's template list. Group admins can save templates, as can members when **Members can create templates** is enabled.

For polls, this replaces **Make a copy**. Voting dates, voters, votes, results, and outcomes remain with the original poll. See [Discussion templates](https://www.loomio.com/docs/en/user_manual/discussions/templates) and [Poll templates](https://www.loomio.com/docs/en/user_manual/polls/poll_templates).

## Thread attachment controls and poll defaults

Thread admins and group admins can enable **Only admins can add attachments** in **Thread settings**. The restriction covers new files and inline images across discussions, comments, poll responses, outcomes, and email replies. Participants can still contribute text, retain existing attachments while editing, and remove attachments.

Discussion and poll templates can supply the restriction for new threads. Polls added to an existing thread follow that thread's setting. Changing a template does not change existing threads.

New threads and new discussion templates now allow multiple polls to run at the same time. Select **Only one poll at a time** to require one poll to close before another starts. Existing threads and templates keep their saved choices. See [Thread settings](https://www.loomio.com/docs/en/user_manual/discussions/using_discussions#thread-settings-and-display).

When importing a discussion template exported by an older release, review **Only one poll at a time** before saving. The importer does not translate the previous poll-concurrency field, so that setting must be selected again if needed.

## Poll editing and voting times

Authorized editors can change a poll's voting method, anonymity, and result visibility before voting opens. Switching between identified and anonymous voting preserves invited voters. Once voting opens, anonymity and voting method are fixed, and results hidden until closing cannot be revealed early.

Previously, saving a poll rounded opening and closing times down to the hour, losing selections such as **23:59**. Hourly opening checks also delayed scheduled polls, particularly in time zones with half-hour or quarter-hour offsets. Polls now retain selected minutes, and background checks run every minute. Voting stops accepting responses at the selected closing time; results and notifications follow as background work completes.

## Invitations and email preferences

Invitation suggestions now show the current group first, followed by group delegates, connected chat rooms, and then other groups. **Everyone in the thread** is offered only for direct threads; in group threads, choose the group. The **Manage voters** window also fits its content. See [Manage voters](https://www.loomio.com/docs/en/user_manual/polls/manage_voters).

Email unsubscribe pages now include **Catch-up emails (all groups)**, so people can change their catch-up schedule without signing in. Thread or group notification settings and the catch-up schedule are saved separately. Choose **Catch-up only** to stop immediate emails while retaining catch-up emails.

## API paths and compatibility

The User API is now `/api/user0`, and the Server API is `/api/server0`. Existing `/api/b2` and `/api/b3` paths continue to work but will be removed in a later release. The `/api/b2` compatibility path retains previous poll field names and reminder values, including the existing protections for hidden participation.

Poll requests and responses on `/api/user0` use clearer participation and scoring names, such as `vote_count_eligible`, `vote_count_cast`, `vote_count_uncast`, `score_min`, and `score_max`. Poll CSV exports also use the new names. Update integrations that consume these exports. The [Upgrading guide](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md#user-and-server-api-paths) lists the field mappings.

Thread settings now use `polls_one_at_a_time`, with the opposite meaning to the previous `allow_concurrent_polls` field. Integrations that set this field must change the name and invert its value, including on the legacy `/api/b2` path; the compatibility adapter does not translate this thread setting.

The Server API key setting is now `SERVER_API_KEY`. The legacy `B3_API_KEY` is read when the new setting is empty or unset. A configured key shorter than 17 characters now prevents Loomio from starting; replace short keys before upgrading. The server key continues to grant instance-wide access. See the [User API](https://www.loomio.com/docs/en/user_manual/integrations/api/user-api) and [Server API](https://www.loomio.com/docs/en/user_manual/integrations/api/server-api) guides.

## Search and membership reliability

Search indexing previously ran during some content saves, increasing request time. Index updates now run after transactions commit in the prioritized `search_index` queue. New and edited content can take a short time to appear in search while workers process the updates.

Adding or reinviting voters previously reset revision flags on unrelated votes, which could deadlock with concurrent membership or account changes. Synchronization now preserves existing vote revisions, avoids unnecessary updates, and retries membership-job deadlocks up to five attempts.

New or changed group handles also respect reserved website paths when the website build supplies a reserved-handle list. Existing handles are preserved.

## Instance dashboard

The admin dashboard now counts people with passwords, passkeys, both, or neither, alongside counts for people who signed in within the last 30 days. These figures describe credentials currently held, including deactivated accounts, rather than the method used to sign in. Each person is counted once per category even if they have several passkeys.

## Security updates

Rack 3.2.7 could retain multipart data until memory was exhausted, accept ambiguous multipart boundaries, return invalid host values in generated URLs, and allow static-header rules to be bypassed through unnormalized paths. Rack 3.2.8 addresses these issues. See the [multipart memory advisory](https://github.com/rack/rack/security/advisories/GHSA-5v64-555j-wjxm), [multipart boundary advisory](https://github.com/rack/rack/security/advisories/GHSA-p8x9-v4hv-2w4g), [host validation advisory](https://github.com/rack/rack/security/advisories/GHSA-2j8w-xcrc-x985), and [static-header advisory](https://github.com/rack/rack/security/advisories/GHSA-wvg4-6p58-3gh3).

## Upgrade notes

Follow the [Upgrading Loomio guide](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md). Upgrade web and worker processes together because this release renames stored poll fields and notification audience values.

Custom worker configurations must serve the new `search_index` queue. Custom recurring-job configurations must include the every-minute scheduled opening and closing checks from `config/recurring.yml`. Restart workers with the updated configuration.

Migrations rename participation and scoring columns, update stored audience names, add attachment settings, and build the scheduled-opening index concurrently. Migration `20261031000002` renames and inverts the saved poll-concurrency setting on all existing threads and discussion templates within its schema transaction. It preserves each saved choice, but holds table locks during those updates and uses a one-second lock acquisition timeout. Large installations should rehearse this migration's duration and read/write impact before deployment; this conversion is not deferred to background jobs.
