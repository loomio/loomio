# Loomio 3.2.0

Loomio 3.2.0 introduces detached anonymous voting, configurable vote-reason
requirements, typo-tolerant search, and an API access page. It also includes
improvements to poll threads, subscription limits, administration, email
replies, self-hosted deployments, and the user manual.

## Anonymous voting

Detached anonymous voting is secure by design: the named electorate and each
submitted ballot are separate records, and Loomio never stores information that
can correlate a ballot with a voter. This includes participant identity,
invitation metadata, submission time, written reasons, and shared identifiers.
The application does not need to hide correlating fields after the fact, as the
previous anonymous voting system did.

Read the [technical summary](../user_manual/changelog/2026-07-26_detached_anonymous_voting.md)
and the [anonymous voting user guide](../user_manual/polls/anonymous_voting/index.md).

This is a significant change. The upgrade path for this conversion is staged
over multiple releases.

### Upgrade path

The transition is staged so an instance can run 3.2.0 while existing polls
finish normally.

As with any upgrade, site owners should make and verify a current backup. If
you need help with the transition, contact Loomio support.

#### Upgrade to 3.2.0

Set `LOOMIO_CONTAINER_TAG=3.2` in your `.env` file, then run `./update.sh`.
New anonymous polls use detached voting. Existing legacy anonymous polls
continue using the old system while they are open. The migration schedules a
conversion job for each topic containing legacy anonymous polls, starting 15
minutes after the deployment so the application code has reloaded. Before the
jobs are enqueued, invalid legacy vote records are cleaned up sequentially.
Each job converts the closed polls in its topic; open polls are skipped. When a
skipped poll later closes, its close operation enqueues the topic conversion
job. The migration preserves choices and aggregate results, with historical
reasons available as read-only text.

3.2.0 does not close open or scheduled polls. They continue normally and are
converted when they close.

Before upgrading to 3.3, make sure the queued anonymous-poll conversion jobs
from 3.2 have finished. The 3.3 database migration will fail if any legacy
anonymous polls remain.

Do not downgrade after detached anonymous polls have been created or legacy
anonymous polls have been migrated. Restore the pre-transition database backup
instead.

## Other highlights

- Poll authors can require reasons for **Disagree** and **Block** responses.
- Open and scheduled polls remain visible in their threads.
- Subscription thread limits include standalone polls and discarded threads.
- Search finds likely matches for misspelled words while preserving permissions.
- Group coordinators have an API access page with User API credentials and
  group IDs. API requests use the `Authorization: Bearer` header.
- Administrators have a dashboard and updated user, group, subscription, API,
  and job management pages.
- Inline image attachment links are repaired automatically, with a dry-run and
  queued repair task available for operators.
- Production assets are preserved across deployments and built into the Docker
  image. Rails is upgraded to 8.1.

## Documentation

The [user manual and guides](../user_manual/overview/index.md) from the
`loomio/loomio-docs` repository are now part of `loomio/loomio`. Keeping them
alongside the application lets feature, interface, and documentation changes
be reviewed and released together. The merged documentation is published at
`www.loomio.com/docs/`.
