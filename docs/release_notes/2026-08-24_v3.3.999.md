# Loomio 3.3.999

This preparation release adds the schema and resumable tooling needed to warm up notification delivery data before a later application release changes the notification architecture. Existing Event-backed notification reads and writes remain unchanged.

- **New:** Additive notification occurrence, delivery, and consolidation-state tables
- **New:** Optional resumable notification consolidation for reducing the later upgrade window

## Notification delivery warm-up

The normal update creates the preparation tables. No separate command is required, and the running application continues to use the existing `events` and `notifications` tables.

Operators with a large notification table can optionally populate the new tables while Loomio remains online:

```sh
bin/rails loomio:consolidate_notifications
APPLY=1 BATCH_SIZE=250000 bin/rails loomio:consolidate_notifications
```

The first command audits the source data without making changes. The second copies legacy notification receipts in committed, resumable batches. Adjust `BATCH_SIZE` for the available database capacity.

The legacy tables remain authoritative in this release. The warm-up does not require maintenance mode, does not change notification delivery, and can be rerun safely. A later notification-delivery release will catch up records created after the warm-up and perform the final cutover during its normal database migration.
