Loomio 3.6.0 is a security and feature release that prevents user-controlled notification values and unsafe Markdown URLs from becoming active markup in email and chatbot messages. It also strengthens group lifecycle and cleanup safeguards and improves web push, demo groups, profiles, and compatibility. Administrators should upgrade promptly.

- **Fix:** Escape user-controlled notification values in email, Matrix, Slack, and Markdown chatbot output
- **Fix:** Reject unsafe URL schemes produced by server-rendered Markdown
- **Fix:** Limit stored reaction values while retaining complex Unicode emoji sequences
- **Fix:** Keep web push available without promoting app installation or reload prompts
- **New:** Create a complete Oatmilk Cooperative demo workspace when demo groups are enabled
- **New:** Show recent visible activity on user profiles
- **Fix:** Stop discarded groups pending permanent deletion from accepting activity or delivering pending notifications
- **Fix:** Make group deletion, account merging, and legacy-data cleanup safer and more recoverable
- **Fix:** Support Safari 16 in current client builds

## Security fixes

Versions through 3.5.1 are affected by both notification-content vulnerabilities described below. Version 3.6.0 contains the fixes. No database backfill is required for either issue because notification content is encoded or sanitized when it is rendered.

### Notification interpolation

A registered user could save HTML in a display name or another notification value. Email and Matrix notification templates interpolated those values into a translated string and then treated the complete string as trusted HTML. Depending on the receiving client, this could display attacker-controlled markup, spoof notification content, or execute script.

Notification email and Matrix renderers now HTML-escape every plain interpolation value while retaining only links generated by the application as trusted markup. Slack and Markdown chatbot renderers treat names and titles as inline text so those values cannot introduce links, headings, formatting, HTML, or additional blocks. Reaction values are limited to 16 Unicode characters; Loomio's longest currently selectable joined emoji uses 10.

See [GHSA-3fgf-67g2-wjgj](https://github.com/loomio/loomio/security/advisories/GHSA-3fgf-67g2-wjgj).

### Server-rendered Markdown URLs

Server-rendered Markdown accepted unsafe and obfuscated URL schemes in generated links and images. User-authored Markdown could therefore produce a clickable `javascript:` link in notification email and other server-rendered HTML, even though literal HTML input was filtered.

The server renderer now checks generated `href` and `src` values with the same URI policy used by Loomio's HTML sanitizer. Unsafe values are replaced before the rendered HTML reaches email or server-rendered pages; normal web, email, telephone, FTP, relative, protocol-relative, and fragment links continue to work.

See [GHSA-gv5m-c7mp-j497](https://github.com/loomio/loomio/security/advisories/GHSA-gv5m-c7mp-j497).

## Web push

Web push is available using the VAPID configuration introduced in Loomio 3.5. Loomio no longer promotes app installation or asks people to reload when its service worker changes. On iPhone and iPad, web push still requires adding Loomio to the Home Screen from Safari.

## Discarded groups and cleanup

Discarding a group now places it and its subgroups unambiguously into a pending-deletion state. Discarded groups block activity, invitation acceptance, reminders, and pending email, push, and chatbot delivery until they are restored.

This release does not enable automatic permanent deletion of discarded groups. A future release will introduce that process and document its grace period before deletion is enabled. Account merges and cleanup tasks preserve or restore dependent records more consistently when work fails.

## Other visible changes

When demo groups are enabled, **Start a demo group** creates a reusable Oatmilk Cooperative workspace with connected discussion, meeting, consent, prioritisation, and STV election examples. Existing installations can enable this with the presence-based `FEATURES_DEMO_GROUPS` setting.

User profiles now show recent discussions, comments, and polls that the viewer is permitted to access. Parent-group members can view subgroup polls where their existing permissions allow it. Client builds support Safari 16.

## Database and API compatibility

This release contains 17 schema migrations plus supporting cleanup code. The migrations normalize stance-choice, membership, tag, and cleanup references, rename the group archive timestamp to the discard lifecycle field, add cleanup indexes, and remove retired Blazer, demo, group-identity, blocked-domain, and other legacy schema.

There are no intended breaking B2 or B3 API changes. Operators with custom database maintenance or reporting that refers directly to removed legacy tables or the old `groups.archived_at` column must update it before deployment.

## Upgrade

Make and verify a current database backup, set `LOOMIO_CONTAINER_TAG=3.6` in `.env`, then run:

```sh
./update.sh
```

The normal update runs all required migrations. Restart every application and worker process so the rendering protections take effect. No security-specific data backfill or environment-variable change is required.

After the release is available, confirm that the application and worker containers report version 3.6.0. Instances running any version through 3.5.1 should upgrade directly to this release.
