This release addresses security vulnerabilities and improves reliability when editing content and choosing meeting times. It also adds tools for self-hosted operators to back up and restore an installation.

- **Fix:** Rails and other dependencies contained security vulnerabilities. Updated versions include the Rails 8.1.4.1 security fixes.
- **Fix:** Time poll outcomes could display meeting times in the device's time zone rather than the profile's time zone. They now use the profile setting.
- **New:** The profile time-zone selector offers a compact regional list with translated labels and retains any currently saved or detected zone.
- **Fix:** Markdown mentions appeared as plain text, and autocomplete could leave the caret before the inserted handle. Mentions now render consistently with rich text, and typing continues after the handle.
- **Fix:** Collaborative editor initialization could duplicate content or restore stale drafts after a format change. Clients now initialize the same saved content consistently, including when the collaboration server is unavailable.
- **Fix:** Choosing **Edit tags** from the inbox could leave existing tags unselected. The form now shows the tags already assigned to the thread's opening post.
- **Fix:** Improved database query performance when loading notifications and reactions.
- **New:** Compose backup and restore scripts package the database, configuration, and supported local files into a portable archive.

## Security updates

Earlier Rails versions contained vulnerabilities affecting uploaded-file processing, parameter handling, client IP detection, HTML helpers, streaming, caching, sessions, and inbound email verification. Rails 8.1.4.1 addresses 21 security issues, including possible arbitrary file access and code execution in Active Storage. See the [Rails security release announcement](https://rubyonrails.org/2026/11/4/Rails-8.0.5.2-and-8.1.4.1-have-been-released) for the advisories.

Other dependency fixes address security advisories in Addressable, HTML sanitization and parsing, Vue I18n, Piscina, serialize-javascript, and Haraka's Joi dependency.

## Meeting times and regional time zones

When sharing a time poll outcome, meeting options previously used the device's time zone even when the person had selected a different zone in their profile. They now use the saved profile time zone, matching the poll's time display.

The profile selector now offers a compact list of regions with translated labels, including separate choices for Canadian regions. A saved or automatically detected zone remains selectable even if it is outside that list. See [Profile time-zone settings](https://www.loomio.com/docs/en/user_manual/users/user_profile#time-zone).

## Editing content and thread tags

Markdown `@handle` mentions previously rendered as plain text, and selecting a mention suggestion could leave the caret in front of the inserted handle. Published Markdown now renders mentions like rich text, and autocomplete leaves the caret after the handle.

The collaborative editor previously depended on synchronization timing to initialize saved content. This could duplicate content or bring back a stale draft after switching formats. Clients now initialize saved content consistently, and the editor can open without waiting for the collaboration server. Older unsaved drafts use different document names after this update; save unfinished edits before upgrading.

When you chose **Edit tags** from the inbox, tags already assigned to the thread's opening post could be missing from the selection. The form now loads and selects those existing tags before opening.

## Query performance

Loading notifications and reactions now requires less database work, particularly for people with access to many threads.

## Backup and restore tools

Self-hosted operators can use `deploy/backup.sh` and `deploy/restore.sh` to create and restore a portable archive containing a PostgreSQL dump, `.env`, local Active Storage files, and supported deployment directories. The backup script also writes a SHA-256 checksum file.

Stop application, worker, email, and collaboration services before taking the backup, as described in the [Backup and restore guide](https://github.com/loomio/loomio/blob/master/deploy/BACKUP_RESTORE.md). The archive contains credentials and must be stored securely. It excludes Docker volumes, Redis, TLS certificates, raw PostgreSQL data, legacy `uploads/`, and externally stored objects; back up external object storage separately.

## Upgrade notes

Follow the [Upgrading Loomio guide](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md). There are no new database migrations since v3.14.0. Save unfinished editor drafts before upgrading.

Rails now restricts the formats FFmpeg can open for media previews and analysis. Installations processing formats outside the default list may need to configure `config.active_storage.ffmpeg_allowed_formats`. Installations using Google Cloud Storage direct uploads must also allow `x-goog-content-length-range` in the bucket's CORS `responseHeader` configuration. The [Rails release notes](https://github.com/rails/rails/releases/tag/v8.1.4.1) describe these changes and the ImageMagick policy requirements for installations using MiniMagick.

See the [full changelog](https://github.com/loomio/loomio/compare/v3.14.0...v3.14.1).
