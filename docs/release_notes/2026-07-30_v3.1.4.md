# Loomio 3.1.4

This security and feature release upgrades Active Storage to address a critical file-read and remote-code-execution advisory. It also adds template sharing, improves mentions, refreshes the interface, and includes security protections that were documented for Loomio 3.1.3 but landed after the `v3.1.3` tag.

Administrators should upgrade promptly and review the Active Storage actions below. This release contains no new database migration and requires no new environment variable.

## Critical Active Storage security update

Rails and Active Storage have been upgraded from 8.0.5 to 8.0.5.1 to address [CVE-2026-66066 / GHSA-xr9x-r78c-5hrm](https://github.com/rails/rails/security/advisories/GHSA-xr9x-r78c-5hrm).

The vulnerability affects applications that accept untrusted image uploads and process variants with libvips. A crafted upload could read files available to the application process, including environment variables and credentials, and could lead to remote code execution.

Active Storage 8.0.5.1 blocks unsafe libvips operations and requires:

- libvips 8.13 or later; and
- ruby-vips 2.2.1 or later.

The Loomio container meets these requirements. Custom installations must upgrade libvips before starting Loomio 3.1.4. The application will refuse to boot when its libvips installation cannot disable unsafe operations.

Upgrading prevents future exploitation but cannot revoke secrets that may already have been disclosed. Operators of an affected installation should assess exposure and rotate secrets available to the application process, including:

- `SECRET_KEY_BASE`;
- the Rails master key and encrypted credentials;
- database credentials;
- Active Storage service credentials; and
- API keys and tokens for external services.

Changing `SECRET_KEY_BASE` ends existing sessions and invalidates signed cookies, signed IDs, and existing signed Active Storage URLs.

## Security protections

This release includes security protections that were documented for Loomio 3.1.3 but were not present in the `v3.1.3` tag:

- API and session authentication boundaries reject unsafe token handling and sensitive serialization.
- User-controlled outbound requests reject private, loopback, link-local, and cloud-metadata destinations.
- User-controlled translated content and Markdown links are protected against executable markup and unsafe URI schemes.
- Direct-upload endpoints require an authenticated Loomio session and apply upload limits.
- Inbound email authentication results are used to avoid attributing spoofed messages to group members.
- Announcement recipient previews enforce the permissions of the target group, thread, or poll.
- Existing discussions, comments, and stances cannot be reassigned to a different parent record through update parameters.

## Template sharing

Discussion and poll templates can now be exported and imported as JSON.

Use **Export json** from a template's action menu. The downloaded filename includes the source group's full name. To import a template, select **New template**, then **Import json**. Importing populates the form without creating a record, so the content and settings can be reviewed before saving.

Template files omit authorship, record IDs, timestamps, attachments, and other ownership metadata. Links from discussion templates to custom poll templates are not exported because those links use instance-specific IDs.

The template action previously called **Fork** is now **Make a copy**, with guidance explaining that the copied template can be adapted before use.

## Mentions and notifications

Typing `@` in the rich-text or Markdown editor now opens mention suggestions immediately. Suggestions are loaded when the editor opens and prioritize:

1. the group mention, when the author has permission to notify the group; and
2. people who were recently active in the thread.

The current user is omitted from the initial suggestions but remains searchable by name or username.

The editor shows the server-calculated number of people who will be notified. Individual and group mentions are combined, overlapping recipients are counted once, group mentions exclude the author, and a direct self-mention includes the author.

## Other changes

- The interface, application branding, icons, typography, navigation, and error pages have been refreshed.
- The emoji picker remembers up to 16 frequently used emoji.
- Rich-text images retain their original aspect ratio.
- Permission-filtered search queries are faster.
- Stale email-read tracking no longer causes notification errors.
- **Copy for AI** has been renamed **Copy Markdown** to describe the exported format directly.
- `until_vote` poll results remain a presentation rule: voting reveals the identified poll's results to that participant.

## Upgrade notes

This release contains no new database migration. Running the normal update command remains safe and ensures the database is current.

1. Edit `.env` and set the image tag:

   ```sh
   LOOMIO_CONTAINER_TAG=3.1.4
   ```

   Use `3.1.4` to pin this release, or `3.1` to track the 3.1 patch series.

2. Run the update script from the deployment directory:

   ```sh
   ./update.sh
   ```

3. Confirm that the application, worker, and inbound-mail services are running.

4. For a custom installation, run `vips --version` and confirm the version is 8.13 or later.

5. Assess whether application secrets could have been exposed before the upgrade and rotate them where required.

No data backfill is required.
