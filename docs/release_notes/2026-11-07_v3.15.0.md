This release makes Loomio faster to open and use, especially on phones and slow connections. It also moves collaborative editing into the main app, so self-hosted operators run one fewer service. Operators should read the upgrade notes before updating.

- **New:** Threads get their data in one round trip to the server instead of three or four. From New Zealand, a medium-sized thread now opens from a cold start in about 2 seconds, down from about 3.7.
- **New:** The first page view downloads about a fifth less JavaScript and a third less CSS.
- **New:** Pages update faster when new content arrives, and refreshing unchanged content no longer redraws the page.
- **New:** Collaborative editing is served by the main app. The separate `hocuspocus` container and subdomain are no longer needed.
- **Fix:** Pasting into a table cell in the collaborative editor could fail with an error and lose the paste. The editor library update removes the code that failed.
- **Fix:** Link previews for threads could include section headings and run paragraphs together. They now show a short, readable plain-text excerpt.

## Faster page loading

Opening a thread used to take three or four round trips to the server for its data: one for the page, then more for the app's configuration and the thread's content. Now the page itself carries the configuration and content, so the data arrives in a single round trip. Each round trip removed saves the full network delay to the server, so the gain is largest far from it.

Loading a medium-sized thread from New Zealand with a cold start, the time until the page was laid out and ready to use fell from about 3.7 seconds to about 2, averaged in Chrome DevTools.

Before, a static preview of the thread showed while the app waited for its content. The app then replaced it with the real page, often shifting the layout several times. Now the thread is drawn once, in its final layout, with far fewer repaints.

Polls, the dashboard's recent threads and polls, the inbox's unread threads and group discussion lists load the same way. Notifications and navigation still load separately.

Signed-in pages also include your groups and memberships at startup, so later pages don't request them again. Reactions now arrive with the content they belong to. Before, they loaded after a short delay and could shift the page as they appeared.

See **Smoother page loading** in the [user changelog](https://www.loomio.com/docs/en/user_manual/changelog).

## Smaller downloads

Measured gzipped, the JavaScript loaded on first view fell from 632 KB to 490 KB, and the CSS linked at startup fell from 71 KB to 46 KB. Most of the saving comes from loading parts of the app only when needed:

- the emoji list loads when you first open the emoji picker;
- poll creation forms and specialised voting forms load when you open them;
- task due-date calendars load when you open them.

## Faster updates in the browser

The app keeps the records it has loaded in a local store. That store has been rewritten. Before, each new batch of data could redraw every part of the page that showed that kind of record, even when nothing had changed. Now only the parts showing changed records update. In tests, re-importing 6,000 unchanged records fell from about 220 ms to about 50 ms and triggered no redraws. This mostly helps live updates and refreshes on slower phones.

## Collaborative editing in the main app

The collaborative editor now connects to `/collab_server` on the app's own hostname. A Ruby collaboration server inside Rails replaces the separate Node `hocuspocus` service. The server identifies people by their session cookie and checks the request's origin. Before, each user's secret token was sent to the browser to sign in to the editor; it no longer is.

When several app processes run, they share document updates over Action Cable pub/sub. If a message is dropped, each process resends its full document state until the others have it.

Tabs left open from an earlier version are prompted to reload, so they connect to the new server.

## Collaborative editor fixes

Pasting into a table cell could fail with "Position tracking requires synchronized editor text", so the paste did not happen. The update to Tiptap 3.33 and y-tiptap 3.2 removes the code that raised this error.

## Upgrade notes

Follow the [Upgrading Loomio guide](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md). There are no database migrations since v3.14.1.

Self-hosted installations need these steps for collaborative editing, also described in the [upgrade guide](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md#collaborative-editing-runs-in-the-app):

- Remove `HOCUSPOCUS_URL` from `.env`.
- Run `docker compose up -d --remove-orphans` to remove the old `hocuspocus` container.
- Remove the `hocuspocus.` DNS record if nothing else uses it.
- If a proxy sits in front of the app, it must pass WebSocket upgrades for `/collab_server`, as it already does for `/cable`.

See the [full changelog](https://github.com/loomio/loomio/compare/v3.14.1...v3.15.0).
