Loomio's deployment is simpler, with fewer services to run, secure, and maintain. This release also expands participation without a group, improves navigation on phones, and strengthens permissions and administrative history. Self-hosted operators should read the migration and compatibility notes before upgrading.

- **New:** Loomio's application runs in a web container and a background job container. Collaborative editing runs inside the web app, removing the separate Node.js `hocuspocus` container and its CNAME, reducing memory overhead and attack surface.
- **New:** Start a poll without a group from **Direct threads**, then invite people through **Manage voters**.
- **New:** Mobile navigation has a revised bottom bar, and pages show content already loaded in the current session while refreshing it.
- **New:** Loomio is available in Korean, including the application and user manual.
- **New:** Voting forms give guidance beside the submit button and use revised Score and Allocate controls.
- **New:** When moving a thread, see how many people would lose participation access and choose to retain them as guests without sending invitations.
- **Fix:** Inviting someone who had already read a thread could fail to grant guest access. Invitations now grant or restore participation while preserving their preferences and read history.
- **Fix:** Replies to votes whose reason was added later could appear at the thread root. Replies now stay under the vote, and an automatic background repair corrects existing threads.
- **Fix:** Locked threads still allowed some edits, outcomes, invitations, and notifications. These actions now require unlocking the thread first.
- **Fix:** Some participation controls offered actions the server would reject. Browser permissions now follow the server's rules, including task completion and voting deadlines.
- **Fix:** The User API's group poll list omitted polls inside discussions. It now includes them alongside standalone polls.
- **Fix:** Some permission, voting-rule, poll-option, and vote-weight changes were missing from history. They are now recorded with the actor where available.
- **New:** Revoked browser sessions are retained for security investigations for 60 days by default, with a configurable retention period.
- **New:** Public sites that enable search indexing have a sitemap and improved pages for crawlers.
- **Fix:** Historical deletions could leave thread entries whose discussion or poll no longer existed. Lists now exclude them, and an operator audit task can report them.
- **New:** The repository includes an early desktop client and further iOS and push-relay preparation. These clients have separate build and deployment requirements.

## Simpler deployment

Loomio's application services are now a web container and a background job container. The web app also serves collaborative editing at `/collab_server` on the main hostname. There is no separate Node.js `hocuspocus` container to deploy, and no `hocuspocus.` CNAME or separate collaboration hostname to configure.

Removing that service simplifies deployment, reduces memory overhead, and reduces the attack surface by removing a separate server and the runtime dependencies operators need to patch. Collaborative editing uses the app's existing session authentication and hostname.

This deployment model was introduced in v3.15.0. Installations upgrading from an earlier version should remove the old Compose service, container, `HOCUSPOCUS_URL`, and unused `hocuspocus.` DNS record. See [Removing the old collaboration service](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md#collaborative-editing-runs-in-the-app) for the steps and WebSocket proxy requirements.

## Direct polls and thread access

You can start a poll without creating a group. From **Direct threads**, open **New**, choose **New poll**, select a template, and invite people through **Manage voters**. The poll appears alongside your direct discussions and is visible only to invited people. See [Direct discussions and polls](https://www.loomio.com/docs/en/user_manual/discussions/direct_discussions).

Moving a thread could leave people able to read it but unable to keep participating. The move form now shows how many people would lose participation access and offers to retain them as guests without sending invitation notifications. Moving to another group requires permission to invite guests in that destination; existing guests keep their access.

When converting a thread to a direct thread, current participants retain access automatically. The guest option also keeps other current members and guests. The person moving the thread and its creator become thread admins. Previously revoked access is not restored by the move, and threads containing anonymous polls cannot be converted to direct threads. See [Moving a thread](https://www.loomio.com/docs/en/user_manual/discussions/using_discussions#move-thread).

Inviting a person who had already read a thread could leave their existing reader record without guest access. Invitations now upgrade that record or restore a revoked guest invitation, preserving notification preferences, read history, and existing admin status.

## Navigation and language

The mobile bottom bar provides the sidebar, dashboard, and notifications, plus a thread menu while reading a thread. Search is available from the dashboard. The title bar shows the page title when its heading scrolls out of view.

Pages display content already loaded in the current session while refreshing it. After startup, Loomio also loads the first dashboard page, recent polls awaiting your vote, and notifications in the background. This does not mark notifications as read. Threads open at the start, with **Latest** to jump to recent activity; links to a particular comment or poll still open that item.

Korean (한국어) is available under **Edit profile → Language**, and Loomio detects Korean browser language settings. Application menus, notifications, time-zone labels, and the user manual are translated.

## Voting and replies

Voting forms now explain what is needed beside the submit button. Score and Allocate use labelled sliders, with number fields for larger ranges. Allocate continues to allow unspent points. Selected ballot options have clearer emphasis, and vote summaries omit fixed scores that add no information. Voter avatars in results are shuffled.

Voting controls could remain available after the poll's closing time had passed. They now disable at the deadline, matching the server's voting rules.

If someone first voted without a reason and added one by editing their vote, replies to that reason could appear at the thread root. New replies now appear under the vote. An automatic background repair fixes existing reply trees, including nested replies, without changing votes or read positions.

## Permissions and history

Locked threads previously allowed some changes, including editing their opening text, setting poll outcomes, inviting people, and sending notifications or reminders. These actions now require unlocking the thread first, including for thread admins. Outcomes also require a closed poll that has not been removed; drafts cannot receive outcomes.

The browser's permission checks now follow the server's rules across threads, polls, comments, memberships, attachments, tags, and tasks. For example, task authors and people allowed to edit a task can tick it as the server permits. New reactions require thread membership and an unlocked thread. Revoked thread readers no longer count as guests or thread admins. Poll exports are available to anyone who can see both the poll and its results, including visitors to public polls.

Instance admins previously bypassed restrictions on groups with inactive subscriptions. Those groups are now read-only for instance admins too. Active and pending subscriptions keep a group working until their expiry; past-due, on-hold, canceled, and expired subscriptions make it read-only. The migration maps unrecognized stored subscription states to canceled.

History previously omitted some changes to thread privacy and locks, group participation permissions, voting rules, poll options, outcome choices, and membership or vote weights. These changes are now recorded. Weight changes retain their actor where available and are stored separately from a person's vote revisions.

Unticking a task in the editor could leave a stale completion timestamp. Unticking now clears it, and completion is determined by that timestamp alone.

## Browser-session retention

Signing out still ends the browser session immediately and removes its browser-push credentials. Previously, the session record was deleted at logout. Loomio now retains its IP address, browser information, and start and end times for security investigations. Revoked sessions cannot authenticate HTTP requests, new realtime connections, or collaborative editing connections.

The default retention period is 60 days after revocation. Operators can set `LOOMIO_SESSION_RETENTION_DAYS` to a nonnegative number; `0` removes revoked records at the next hourly cleanup. Permanently deleting an account removes its session history. See [Signing in and out](https://www.loomio.com/docs/en/user_manual/users/signing_in#sign-out).

## API, crawlers, and exports

The User API's group poll list previously returned only polls that started their own thread. `GET /api/user0/polls` now also includes polls inside discussions, with their current outcomes, while preserving topic visibility and hidden-result rules. Integrations can match discussions and polls by `topic_id`. See [List polls](https://www.loomio.com/docs/en/user_manual/integrations/api/user-api#list-polls).

Crawler pages now provide paginated public activity, canonical URLs, and structured discussion metadata. When `ALLOW_ROBOTS` is present, `/sitemap.xml` lists public groups, threads, and standalone polls, and `robots.txt` points to it. Private content remains excluded. Without that setting, indexing remains disabled and the sitemap is unavailable. Export pages remain marked against indexing.

Crawler and export pages could fail when a contribution's author no longer existed. They now display a deactivated-user label. Link previews use readable plain-text excerpts with absolute image URLs.

Historical deletions could also leave topic records after their discussion or poll had gone. Topic lists now exclude these entries. Operators can report affected records with the `loomio:orphan_topics` audit task.

Integrations consuming the shared browser JSON serializers need to account for two field changes: task records now expose `done_at` instead of `done`, and group records expose raw `subscription.state` and `subscription.expires_at` instead of `enabled` and `subscription.active`. An active subscription has state `active` or `pending` and no expiry or a future expiry; a discarded group remains disabled. Older group exports with task `done` fields can still be imported.

## Native-client development

An early Qt 6 desktop client can connect to several Loomio hosts, with isolated web profiles, a combined activity list, and native notifications. It signs in through the system browser and stores refresh tokens in the system keychain. The server now recognizes the desktop client with a loopback callback and scopes that exclude push-relay registration. The client is not released; see [Desktop development](https://github.com/loomio/loomio/blob/master/desktop/README.md) for build requirements.

The iOS app has Loomio branding, confirmed host shortcuts, and TestFlight build configuration. Push-relay preparation includes separate sandbox and production APNs keys, application-level rate limiting, and deployment instructions. Production relay deployment and physical-device push verification remain pending. This server release does not install or configure either native client or the relay. See [iOS development](https://github.com/loomio/loomio/blob/master/ios/README.md) and [Push relay deployment](https://github.com/loomio/loomio/blob/master/push-relay/deploy/README.md).

## Upgrade notes

Follow the [Upgrading Loomio guide](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md). There are eight new migration files since v3.15.0. They add and rename a discussion-change timestamp, reconcile task completion and remove `tasks.done`, replace `login_tokens.used` with `used_at`, add session revocation tracking and its concurrent index, normalize subscription states, and schedule targeted vote-reply repairs. The earlier vote-reply scheduling migration is superseded and does not enqueue work.

If upgrading from before v3.15.0, follow [the collaboration-service removal steps](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md#collaborative-editing-runs-in-the-app) to remove the old Node.js `hocuspocus` service and container. Updating only the app image tag does not remove that service from your Compose configuration.

Stop old web and worker processes before migrating, then restart both with the new version. The removed and renamed columns are incompatible with older processes. Retained revoked sessions also require the new authentication checks: starting older code against those records could make logged-out sessions valid again. A rollback must restore a compatible database and remove retained revoked credentials before older authentication code runs.

Migration `20261113000001` identifies threads with misplaced vote replies, newest affected threads first, and schedules one `RepairTopicWorker` job per thread ten minutes later on the `low` queue. Restart workers with the new code before those jobs start and ensure custom worker configurations serve that queue. Each job rebuilds its thread under the existing write lock, preserving votes, read positions, and notifications. Completed repairs can safely be repeated. No manual repair command is needed.

See the [full changelog](https://github.com/loomio/loomio/compare/v3.15.0...v3.16.0).
