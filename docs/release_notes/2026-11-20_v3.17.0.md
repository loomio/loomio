Loomio 3.17 is a security and maintenance release led by patched versions of Ruby and Nginx. Self-hosted operators using the bundled Docker Compose setup should check the proxy settings in the upgrade guide before pulling images.

- **Fix:** Earlier Ruby and Nginx versions contained security vulnerabilities. The Loomio app image includes Ruby 4.0.10, and the Compose proxy image uses Nginx 1.31.9.
- **Fix:** The web server and mail stack also used dependencies with known vulnerabilities, and deployment credentials could enter the Docker build context. The release updates those dependencies and excludes local credential files from builds.
- **New:** Instance admins can manage spam rules and see how often each rule blocks activity.
- **New:** On sites with subscriptions, invitation allowances count distinct recipients and respect extended trial limits.
- **Fix:** Permanent deletion could leave files and nested replies behind. Loomio now removes the replies and queues their unshared files for deletion.
- **Fix:** A live group update could disable guest invitations in the browser. The browser now keeps the group’s guest settings across updates.
- **Fix:** A thread form could let people compose a discussion the server would reject. It now checks permission before they start writing.
- **Fix:** A failed sign-up request could leave the form unusable, and an invalid browser time zone could break date formatting. The form now supports retries, and date formatting falls back to UTC.
- **Fix:** The support form could still accept submissions after an operator disabled it. The server now enforces the setting.
- **Fix:** Rendering an embedded YouTube preview depended on the server fetching metadata from YouTube. Loomio now builds the thumbnail link from the video ID.
- **New:** The companion iOS app can stay connected to several Loomio servers, and its optional push relay now uses Ruby and SQLite.

## Ruby and Nginx security updates

Earlier Ruby versions contained security vulnerabilities in regular expression processing and string case conversion. Loomio’s app image uses Ruby 4.0.10, which fixes them. [Ruby security advisories](https://www.ruby-lang.org/en/news/2026/11/18/multiple-vulnerabilities-in-regexp-and-string/)

Earlier Nginx versions contained security vulnerabilities including HTTP/2 memory corruption and a TLS request handling issue. The Loomio Compose proxy image uses Nginx 1.31.9, which fixes these issues. Existing Compose installations should update the proxy image settings in `.env` when upgrading. [Nginx security advisories](https://nginx.org/en/security_advisories.html) · [Compose upgrade steps](https://github.com/loomio/loomio/blob/master/deploy/UPGRADING.md#v3170)

Earlier versions also shipped affected versions of Puma, MessagePack, and Haraka’s XML parser. This release updates them to Puma 8.0.3, MessagePack 1.8.7, and fast-xml-parser 5.12.1. The application Docker build now excludes local `.env` files, Kamal secrets, and matching deployment configuration backups. [Puma security notes](https://github.com/puma/puma/releases/tag/v8.0.3) · [MessagePack advisory](https://github.com/advisories/GHSA-73v3-wf97-vpgj) · [XML parser advisory](https://github.com/advisories/GHSA-474x-hrwr-fgx4)

## Spam rules and invitation allowances

Under **Site administration → Spam rules**, instance admins can add rules for IP addresses and networks, email domains, and regular expressions. Rules can expire, be disabled and restored, or be tested against a sample value. Activity shows 30 days of aggregate counts by type of blocked action without storing the attempted values. IP rules apply to signed-in and signed-out requests. Email rules also cover existing accounts, invitations, and outgoing Loomio mail.

On sites with subscriptions, non-paying accounts can invite the same people again without using more of their allowance. An extended trial membership limit increases the invitation allowance. A separate abuse limit can apply across trial accounts sharing an IP address.

## Permanent deletion

Permanent deletion could leave nested replies in the database and attachments, inline images, group logos, or cover photos in file storage. Loomio now removes dependent replies and queues eligible files for removal after the deletion commits. Ordinary discard still retains files, and files attached to surviving content remain available. [Deletion fix](https://github.com/loomio/loomio/pull/13089)

## Thread creation and guest invitations

A live update could replace the group’s subscription settings with an incomplete set and disable guest invitations until the page reloaded. Live updates now carry the same subscription capabilities as the page load. These group-level settings and limits are included for anyone who can see the group, and the subscription renewal date is no longer included in these group payloads.

People could open a new discussion form and write a draft before finding out that they lacked permission to start the thread. The form now applies the server’s creation rules before presenting the editor. On sites with open sign-up, people need to belong to a group before starting a direct discussion.

## Sign-up, dates, and contact forms

A failed sign-up request could make the form unusable. Loomio now displays the error, keeps the form available, and lets the person try again. Browsers that return an invalid time zone could break date formatting. Loomio now uses UTC when it can’t use the detected zone.

Turning off the contact form previously hid it while leaving the submission endpoint active. The server now rejects submissions when `FEATURES_SHOW_CONTACT` is unset or empty.

## Video previews

Rendering HTML with an embedded YouTube video used to fetch metadata from YouTube. Loomio now uses the video ID to render a linked thumbnail. Other iframe embeds are rendered as links.

## iOS companion and push relay

The iOS app source now supports signing in to multiple Loomio servers, switching between them, and viewing one activity list with each item labelled by server. Existing connections carry over when updating the iOS app. Its separate push relay uses Ruby and SQLite and retains the v1 protocol. Installations running the Node.js prototype need a fresh SQLite database when deploying the new relay. The iOS build and relay use their own release and deployment procedures. [iOS app](https://github.com/loomio/loomio/tree/master/ios) · [Push relay deployment](https://github.com/loomio/loomio/blob/master/push-relay/deploy/README.md)
